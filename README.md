# متجر ذكري

React + Vite، موقع ثابت بدون باك إند أو اشتراك قاعدة بيانات. الصور الأصلية محفوظة كما هي، ونسخة العرض داخل public/images.

## التشغيل

ثبّت Node.js ثم افتح Terminal في المجلد:

```sh
npm install
npm run dev
```

لبناء ملفات الرفع: `npm run build`، الناتج في `dist`. للاختبارات: `npm test`.

## تعديل المنتجات

افتح `src/catalog.js`. كل سطر منتج فيه:

- `id`: كود فريد ثابت لا تكرره.
- `name`: اسم العطر.
- `category`: men أو women أو unisex. كل المنتجات تظهر تلقائيًا في New Arrivals.
- `image`: اسم الصورة داخل public/images، بنفس الحروف الكبيرة والصغيرة.
- `size`: الحجم بالملليلتر.
- `price`: السعر بالجنيه، رقم بدون علامات اقتباس.
- `soldOut`: غيّر false إلى true ليظهر SOLD OUT ويتوقف زر الإضافة. لا توجد إدارة مخزون تلقائية.

لإضافة منتج، ضع صورته في public/images وانسخ سطرًا وعدّل القيم والكود. شغّل build ثم ارفع النسخة الجديدة، أو ادفع التعديل إلى GitHub لو الاستضافة مرتبطة به.

**الأسعار والشحن مبدئية بطلبك، راجعها قبل إطلاق البيع.** أسعار الشحن للمحافظات الـ27 موجودة في نفس الملف تحت shipping. الشحن الحالي مبلغ ثابت لكل طلب حسب المحافظة.

بيانات الدفع في store: ضع حساب InstaPay في instapay ورقم المحفظة في wallet بين علامتي الاقتباس. رقم واتساب ليس مفترضًا أنه رقم محفظة. عندما تكون البيانات فارغة، الموقع يطلب من العميل التواصل لتأكيد بيانات التحويل قبل الدفع.

## أين تصل الطلبات؟

1. العميل يضيف منتجاته ويكتب اسمه وموبايله ومحافظته وعنوانه.
2. يختار طريقة الدفع، ويشاهد إجمالي المنتجات والشحن.
3. يراجع رسالة الطلب ثم يفتح واتساب ويضغط إرسال بنفسه إلى 01500573883.
4. يرفق Screenshot التحويل يدويًا في المحادثة. رابط واتساب لا يرفق صورة تلقائيًا.
5. ستجد الاسم والعنوان والهاتف والمنتجات والكميات والإجمالي وطريقة الدفع في محادثة واتساب.
6. راجع وصول الفلوس فعليًا إلى الحساب، وطابق السعر والشحن والتوفر قبل تجهيز الطلب. الإسكرين وحده ليس تحققًا آليًا للدفع.

لا توجد لوحة طلبات أو قاعدة بيانات في هذه النسخة. فتح واتساب أو تجهيز الرسالة لا يضمن وصولها؛ لو لم يضغط العميل إرسال فلن يصل طلب. بيانات العميل تبقى مؤقتًا في ذاكرة الصفحة وتنتقل لواتساب عند اختياره، ولا تحفظ في localStorage. السلة فقط تحفظ على جهاز العميل. معرف الطلب مرجع للمحادثة وليس سجلًا مركزيًا.

يمكن تنظيم الطلبات بتصنيفات WhatsApp Business (بانتظار الدفع / مدفوع / تم الشحن). للحصول على لوحة إدارة ومخزون مركزي مستقبلًا ستحتاج خدمة تخزين وهوية، وقد تستخدم خدمة بخطة مجانية ضمن حدودها؛ عدم شراء سيرفر لا يمنع وجود باك إند مستضاف.

## الاستضافة والدومين

Vercel Hobby المجاني غير مسموح للمتاجر التجارية طبقًا لشروطه؛ الكود يعمل تقنيًا عليه لكن الاستخدام التجاري يحتاج خطة مناسبة:
https://vercel.com/docs/limits/fair-use-guidelines

بديل للموقع الثابت: Cloudflare Pages، لديه خطة مجانية بحدود استخدام، ويمكن ربط دومين. تعليمات React الرسمية:
https://developers.cloudflare.com/pages/framework-guides/deploy-a-react-site/

عند ربط GitHub: أمر البناء `npm run build`، مجلد الناتج `dist`. أو استخدم Direct Upload لرفع محتوى dist. أضف الدومين من إعدادات المشروع واتبع سجلات DNS التي تعرضها المنصة. لا تضع أسرارًا أو بيانات عملاء في ملفات الموقع؛ كل الملفات المنشورة عامة.

على Vercel بخطة تسمح بالاستخدام التجاري: Framework = Vite، Build = npm run build، Output = dist. لا يحتاج المشروع متغيرات سرية أو Functions. لم يتم شراء دومين أو نشر الموقع من هذه الجلسة.

## قبل البيع

راجع الأسعار والشحن وأسماء العطور، أضف بيانات التحويل المؤكدة، وحدد سياسة الاستبدال والشحن الفعلية مع العميل. اختبر طلبًا حقيقيًا من موبايلك للتأكد من وصول الرسالة والإسكرين. الحالة SOLD OUT تتغير في ملف المنتجات ثم إعادة النشر.

## أوصاف العطور

الأوصاف والـGreen/Red Flags والنوتات في src/fragranceDetails.js، مرتبطة بكود كل منتج id. اضغط الصورة أو اسم العطر لفتح التفاصيل. خانة reference تحفظ الربط الذي أرسلته بين عطور ذكري والأسماء المرجعية ولا تظهر للعميل. لإضافة وصف لمنتج جديد، أضف سجلًا بكوده في نفس الملف.
